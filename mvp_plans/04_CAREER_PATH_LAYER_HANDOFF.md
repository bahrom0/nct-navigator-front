# Phase 4 — Career Path Layer

## Цель

Сделать так, чтобы пользователь выбирал не отдельный код НЦТ, а понятный путь к желаемой профессии.

**Код НЦТ — способ поступления, а не конечная цель.**

## Как работает сейчас

```text
Интересы → список подходящих кодов → выбор кода → Interview → общий Plan → Coach
```

- AI оценивает совпадение специальностей с интересами.
- Профессии остаются короткими подписями на карточках.
- `ai_v2` не формирует полноценный профессиональный маршрут.
- В Interview/Plan передаётся в основном код и название специальности, поэтому дальнейший план получается общим.
- Пользователь сам должен догадаться, какой вариант действительно приведёт его к нужной профессии.

## Проблема

Например, человек хочет стать **учителем информатики**. Система может показать педагогические и IT-коды, но не объясняет:

- какой вариант является прямым путём;
- почему стоит выбрать именно его;
- что даст выбранная специальность;
- чего в ней не хватает;
- какие шаги потребуются после поступления.

Текущая ошибка AI-задачи: модель отвечает на вопрос «какие специальности похожи на интересы», хотя должна отвечать на вопрос «кем хочет стать пользователь и какой подтверждённый маршрут приведёт его к этой профессии».

## Как должно работать

```text
Интересы
  → профессиональная цель
  → один уточняющий вопрос, если он меняет решение
  → рекомендуемый карьерный маршрут
  → коды НЦТ и вузы внутри маршрута
  → долгосрочный путь до профессии
  → ближайшие задачи в Coach
```

На экране сначала показывается профессия, например **«Учитель информатики»**, затем:

1. один рекомендуемый путь;
2. одна разумная альтернатива;
3. смежный путь только с явно указанным пробелом;
4. конкретные коды как варианты поступления внутри этих путей;
5. краткое объяснение «что даёт / чего не даёт / что делать дальше».

Основное действие: **«Выбрать этот маршрут»**, а не выбор кода как конечной цели.

## Решение

1. **Profession Target Resolver** — определяет основную профессию по интересам и задаёт один полезный уточняющий вопрос при неоднозначности.
2. **Career Route Builder** — связывает профессию, необходимые компетенции, семейства специальностей и реальные записи НЦТ.
3. **Decision Layer** — выбирает один основной маршрут и одну альтернативу вместо списка равноправных карточек.
4. **Route Snapshot** — сохраняет профессию, выбранный путь, основной код, альтернативы, пробелы, основания и уверенность.
5. **Передача контекста** — Interview, Plan и Coach используют выбранную профессию и маршрут без потери данных.

Маршруты должны различаться как `direct`, `bridge` и `adjacent`. AI может сравнивать и объяснять их, но не может придумывать коды, вузы, официальные требования или отсутствующие факты.

## Роль AI

AI должен:

- понять профессиональное намерение за комбинацией интересов;
- отличить прямой путь от похожего или смежного;
- выбрать лучший подтверждённый вариант для условий пользователя;
- объяснить решение простым языком;
- честно показать пробелы и неопределённость;
- передать структурированный маршрут следующим модулям.

Это описание требуемого поведения, а не готовый буквальный prompt.


## Примечания

- В каталоге уже есть `informatics_teacher` и связанные специальности, но новый `ai_v2` пока не использует этот слой как полноценный маршрут.
- Непроверенные knowledge-карточки нельзя называть официально подтверждённым путём: нужны источник, версия и статус проверки.
- Старые цели пользователей должны остаться рабочими; новый route snapshot добавляется обратно совместимо.
- Career Path хранит долгосрочную дорогу, а Coach выполняет её ближайший отрезок на 1–12 недель.
- Первый сквозной сценарий для проверки: **IT + Педагогика → Учитель информатики → маршрут → Interview → Plan → Coach**.

## Результат

Пользователь должен понимать: **кем он может стать, какой путь рекомендуется, какой код выбрать, почему именно его и что делать дальше**.
